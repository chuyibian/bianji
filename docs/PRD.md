# 产品需求文档：便记（PWA 排便记录）

**作者**：cy.bian
**日期**：2026-10-29
**状态**：Draft v1（已通过 grill me 访谈确认 10 项关键决策）

---

## 1. 概要

做一款模仿 iPoop 核心功能的手机网页应用（PWA）：首页一键记录一次排便，右上角「日历」全览历史，右上角「数据」查看统计。用户用浏览器打开并「添加到主屏幕」即可安装，不需要 App Store；数据只保存在手机本地，不需要账号。

## 2. 背景

- **问题**：排便频率和形状是肠道健康最直接的信号，医生问诊时常会问「多久一次、什么形状」，但大多数人凭记忆回答，并不准确。
- **现有方案**：iPoop 等原生 app 需要从商店下载，有的需要注册或付费，还会把健康数据上传到云端。
- **机会**：一个零门槛（打开网址即用）、零账号、数据不出手机的极简记录工具。

## 3. 目标与非目标

**目标**
1. 记录一次排便只需 **1 次点击**，用时不超过 1 秒。
2. 补充形状和体感只需 **2 次额外点击**，而且可以跳过。
3. 能在日历上回看任意一天的记录，并修正错误。
4. 统计页能回答四个问题：多久一次、一般几点、形状是否正常、是否顺畅。

**非目标**
1. **不做账号和云同步**：避免运营后端，也避免健康数据的隐私合规问题。换机靠 JSON 备份文件。
2. **不做医疗诊断**：统计页只给「偏便秘 / 正常 / 偏稀」的参考提示，并附免责声明。
3. **不记录颜色、量、备注、时长**：访谈中明确去掉，保持表单最短。
4. **首页只放「距上一次」**：不显示今日次数，也没有撤销提示；误触时可以在详情面板或日历里删除。
5. **不做多语言**：只做中文界面。
6. **不做提醒推送**：iOS 上 PWA 推送需要额外授权，收益低。

**成功指标**（个人工具，以自用为准）
| 指标 | 当前 | 目标 | 测量方式 |
|---|---|---|---|
| 记录耗时（点击图标到保存成功） | — | ≤ 3 秒（含启动） | 手动计时 |
| 详情补充率 | — | ≥ 60% 的记录带有形状 | 统计页数据 |
| 连续使用 | — | 连续 30 天每天都有记录 | 日历 |
| 离线可用 | — | 飞行模式下三个页面均可正常使用 | 手动测试 |

## 4. 目标用户

- **主要用户**：关注肠道健康的个人，例如有便秘或肠易激困扰、正在调整饮食、或需要给医生提供记录的人。
- **使用场景**：在卫生间里或刚出来时单手操作，可能是在公共场所，因此界面风格要**克制**，不用 emoji 和夸张插画，打开也不尴尬。

## 5. 用户故事与需求

### P0：必须有

| # | 用户故事 | 验收标准 |
|---|---|---|
| R1 | 作为用户，我想一键记录一次排便 | 首页有一个大圆形「记录」按钮（左上角是日历，右上角是数据）；点击后立即以当前时间保存一条记录，按钮给出按压反馈和「已记录」状态 |
| R1a | 作为用户，我想知道离上次过了多久 | 首页有「距上一次」卡片，格式为「N天N小时」，不足一天只显示小时；每 30 秒刷新一次；点击卡片可以编辑最近一条记录 |
| R2 | 作为用户，我想顺手补充形状和体感 | 保存后从底部弹出详情面板：布里斯托 1–7 型（单选，带示意图和名称）、体感（顺畅 / 费力 / 疼痛，单选）；点选后即时写入该记录；「完成」或点击遮罩关闭；全部不选也可以 |
| R3 | 作为用户，我想在日历上全览记录 | 右上角「日历」进入月视图，周一开头；每个有记录的日期显示次数；可以切换上月和下月，并有「今天」按钮回到本月 |
| R4 | 作为用户，我想查看并修改某一天的记录 | 点击日期，下方列出当天各条记录（时间、形状、体感），按时间排序；点击一条打开编辑面板，可改时间、形状和体感，也可删除（需二次确认） |
| R5 | 作为用户，我想补录忘记记的记录 | 日详情里有「补录」按钮，打开编辑面板，日期为所选日期，时间默认 12:00 且可调整，保存后出现在列表中 |
| R6 | 作为用户，我想看统计概览 | 右上角「数据」进入统计页；可切换范围：近 7 天 / 近 30 天 / 近 12 个月；概览卡片：总次数、日均次数、距上次（全局）、最长间隔（范围内） |
| R7 | 作为用户，我想看频率趋势 | 柱状图：7 天和 30 天按日显示，12 个月按月显示；没有数据的柱子高度为 0，但保留位置 |
| R8 | 作为用户，我想知道我一般几点去 | 24 小时分布柱状图（0–23 时），标出最高频的时段 |
| R9 | 作为用户，我想知道形状和体感是否正常 | 布里斯托 1–7 型占比条，以及体感三档占比条；根据有形状的记录，提示「偏便秘（1–2 型多）/ 正常（3–5 型）/ 偏稀（6–7 型多）」；底部附「仅供参考，不构成医疗建议」 |
| R10 | 作为用户，我想安装到主屏幕并离线使用 | 提供 manifest 和图标，iOS Safari 和安卓 Chrome 都能添加到主屏幕并全屏启动；Service Worker 缓存全部静态资源，飞行模式下可以正常打开和记录 |
| R11 | 作为用户，我不想丢数据 | 数据存在本地；统计页底部的「数据备份」提供「导出备份」（下载 JSON 文件）和「导入备份」（选择 JSON 文件，按记录 ID 合并去重，导入后提示新增条数）；首次启动时申请持久化存储 |

## 6. 方案概述

**页面结构**（hash 路由，三个页面）
```
#/           首页：仅「记录」按钮；右上角 [日历] [数据] 两个图标
#/calendar   日历：返回 | 月份切换 | 月格子 | 当日记录列表 + 补录
#/data       数据：返回 | 范围切换 | 概览 | 趋势 | 时段 | 形状/体感 | 数据备份
```

**数据模型**
```json
{ "id": "lq3k9x-a1b2", "ts": 1761724800000, "bristol": 4, "feeling": "smooth" }
```
- `ts`：毫秒时间戳，按本地时区显示。
- `bristol`：取值 1–7，或 `null`（未填）。
- `feeling`：取值 `smooth`（顺畅）、`strain`（费力）、`pain`（疼痛），或 `null`。
- 备份文件格式：`{ "app": "bianji", "version": 1, "exportedAt": ..., "records": [...] }`。

**布里斯托分类文案**
| 型 | 名称 | 提示 |
|---|---|---|
| 1 | 分离硬块 | 便秘 |
| 2 | 结块香肠状 | 轻度便秘 |
| 3 | 表面有裂纹 | 正常 |
| 4 | 光滑柔软 | 理想 |
| 5 | 软团块 | 正常偏软 |
| 6 | 糊状 | 轻度腹泻 |
| 7 | 水样 | 腹泻 |

**技术决策**
| 决策 | 选择 | 理由 |
|---|---|---|
| 交付形式 | PWA | iOS 和安卓通用，无需商店（访谈问题 1） |
| 框架 | 原生 HTML/CSS/JS，无构建步骤 | 文件夹可以直接上传 EdgeOne Pages；没有依赖需要维护 |
| 存储 | `localStorage`，单个 key 存 JSON 数组 | 数据量很小（每年约 500 条，不到 50KB），API 最简单；在 iOS 上它与 IndexedDB 受同样的清理策略约束，真正的防丢靠导出备份和 `navigator.storage.persist()` |
| 图表 | 手写 SVG/CSS 柱状图 | 只有柱状图和占比条，不值得引入图表库 |
| 视觉 | 参照 Apple 健康：大标题、分组白卡片、圆体数字配灰色小单位、带网格线和顶部读数的图表、iOS 风格的底部面板；主色用 iOS systemBrown，配色都取自 iOS 系统色 | 访谈问题 10，v2 改版 |
| 部署 | 腾讯 EdgeOne Makers，加速区域选「全球（不含中国大陆）」，用默认项目域名，不绑自定义域名，仅供个人使用 | 访谈问题 9，教程见 `docs/DEPLOY-EdgeOne.md` |
